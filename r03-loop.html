0.3第零幕 · 为什么需要 RAG·PIPELINE

一个 RAG 系统的最小闭环

把 RAG 拆到最小，只有两条线七个动作。这一页给出完整骨架，并标出每一步最典型的失败方式——后面每个部分，都是在给其中某一步打补丁。

这一页在整条链路上的位置
对应环节全链路地图 · 后面所有内容都挂在这张图上
不学卡在哪不知道自己卡在哪一步，优化时东改一下西改一下，改完不知道有没有变好。
它解决什么给出七个动作和各自失效方式，让「效果不好」变成可定位的问题。

1整条链路只有两条线

不管后面加多少优化，RAG 系统的骨架永远是两条线：

离线阶段（Indexing）平时做

把一堆杂乱的文件，变成「能被快速查到的知识库」。这条线只跑一次，或者定期跑。

代表动作：解析 → 分块 → 向量化 → 入库。

在线阶段（Retrieval & Generation）考时做

用户提问的那一刻开始跑，必须在一秒左右结束。

代表动作：检索 → 增强 → 生成。

这两条线的关系是：离线的质量决定了在线的上限。如果文档解析漏了表格、分块切断了句子、向量模型不懂你的领域，在线阶段无论怎么优化提示词都救不回来。

2离线：四步，一步都不能省

① 解析PDF/Word/网页 → 纯文本
→
② 分块长文 → 小卡片
→
③ 向量化文字 → 数字坐标
→
④ 入库坐标 + 原文 → 向量库
步骤做什么典型失败后果
① 数据解析提取文字、表格结构、图片里的文字；去掉页眉页脚、乱码、广告扫描件没 OCR、表格被拍平成一行字符串后面全错，且很难察觉
② 文档分块把长文切成几百字的片段，相邻片段保留重叠从句子中间切断、把标题和正文分开检索到的片段看不懂
③ 向量化用嵌入模型把每块文字变成向量用了通用模型，不懂行业术语语义相近的查不到
④ 入库向量 + 原文 + 元数据存进向量库，建索引没存元数据（来源、页码、部门）无法溯源、无法做权限过滤

一句话总结这条线的价值：「垃圾进，垃圾出」。RAG 效果差的时候，八成问题出在这一半，而不是模型。

3在线：三步，每一步都可能翻车

① 检索问题 → 向量 → Top-K
→
② 增强片段填入提示词模板
→
③ 生成模型读资料作答

以「我们公司出差住宿的报销标准是多少」为例，走一遍：

  1. 检索：用同一个嵌入模型把问题变成向量，去库里比对，取最相似的 3 到 5 块。
  2. 增强：把这些片段填进一个预设模板的「参考资料」区，问题填进「提问」区，再加一句约束：「严格依据资料回答，资料未提及请回答不知道」。
  3. 生成：模型读完资料，组织成一句通顺的话。

三步各自的翻车方式完全不同，这也是后面要分三个环节优化的原因：

环节典型翻车该往哪优化
检索资料没找出来，或找出来的是无关内容改写查询、混合检索、重排
增强资料太多把关键信息淹了、模板没约束住压缩上下文、调整模板、控制顺序
生成资料对，模型答歪了或夹带私货强化约束、要求引用、Self-RAG 校验

很多团队一遇到效果不好就去改提示词，其实应该先看检索出来的那几块到底对不对。如果资料本身就是错的，提示词写得再漂亮也只是让错误答案更通顺。

4这五步，就是后面五个部分

本课部分对应链路要解决的问题
第一部分 · 离线索引解析、分块、向量化、入库怎么把资料整理成「好查」的状态
第二部分 · 在线问答检索、增强、生成怎么把资料「用对」
第三部分 · Advanced RAG在三个环节上加优化朴素方案不够用时的系统性补强
第四部分 · Graph RAG改变知识的组织形态跨越文档的全局性问题
第五部分 · Agentic RAG改变控制流让系统自己决定查什么、查几次
第六部分 · 评估横切所有环节判断问题到底出在检索还是生成

注意最后一行：评估是横切的。没有评估，你在做优化时无法判断改动是变好还是变坏，只能凭感觉调参——这是 RAG 项目最常见的死法。

本页要点

  1. RAG 只有两条线：离线建库（解析→分块→向量化→入库）、在线问答（检索→增强→生成）。
  2. 离线质量决定在线上限；在线效果差时，先查检索出来的原文片段对不对。
  3. 三个环节的失效方式不同，优化手段也不同，不能用提示词去补检索的锅。
  4. 评估横切所有环节，没有评估的优化都是瞎调。

9自测

Q1线上效果不好，第一步应该查什么？
先定位是「资料错」还是「模型没用对」。如果检索出来的片段就是不相关的，改提示词毫无意义。这是 RAG 调试最基本的一条纪律。
Q2离线阶段漏做「元数据入库」（来源、页码、部门），会导致什么？
元数据不影响相似度计算，但它决定了两个能力：可溯源（告诉用户「依据在哪」）和权限隔离（A 部门查不到 B 部门）。企业落地时这两条往往比准确率更优先。
Q3「相邻片段保留重叠」的直接目的是？
分块边界必然有损失。overlap 让被切断的句子在两块里各保留一部分，至少有一块能读懂。代价是存储和检索结果里会出现重复内容。
