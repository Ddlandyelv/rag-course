检索中：混合检索与融合

向量懂语义但抓不住型号，BM25 抓得住字面但不懂同义。这一页讲怎么把两条腿绑在一起，以及 RAG Fusion、父子索引两种进阶玩法。

1两条腿走路：向量 + 关键词

0.4 页说过：向量检索懂语义，但对精确字符串不敏感；BM25 死磕字面，但不懂同义。两者的短板恰好是对方的长板。

查询向量检索BM25混合检索
「怎么退货」命中「退货流程」相关段落 ✓可能命中「退款」「售后」但排序一般两路都命中，排序更稳
「A-102 滤芯」返回一堆型号相近的结果 ✗精确命中 A-102 ✓精确项排最前
「发票丢了能补吗」命中「发票遗失处理」✓字面不重合，几乎不命中靠向量兜住

所以工业界的标准做法是：两路并行检索，再融合排序。融合算法最常用的是 RRF（Reciprocal Rank Fusion）。

2RRF：只看排名，不看分数

两路检索的分数量纲完全不同（余弦相似度 0–1，BM25 可能几十上百），不能直接相加。RRF 绕开了这个问题——它只用排名，不用分数：

RRF(d) = Σi　1 / (k + ranki(d))　　（k 通常取 60）

含义：某文档在每一路里的排名越靠前，贡献越大；在任一路里没出现，就不贡献。最后按总分排序。

文档向量排名BM25 排名RRF 得分结果
D11—1/61 ≈ 0.0164第 1
D2321/63 + 1/62 ≈ 0.0320第 1（反超）
D3—11/61 ≈ 0.0164并列

注意 D2：它没有在任一路拿第一，但两路都在前列，RRF 会把它顶上来。这正是融合的价值——两路都认可的，比一路力挺的更可信。

3RAG Fusion：把一次查询变成好几次

RAG Fusion 在混合检索之上再加一层：让模型把原问题改写成多个不同角度的查询，分别检索，再用 RRF 融合。

原问题怎么提高复购率
→
生成 4 变体留存 / 会员 / 召回 / 频次
→
各查一次4 组结果
→
RRF 融合统一排序
→
取 top-K交给模型

它解决的是单一表述的覆盖盲区：用户说「复购率」，文档里可能写的是「留存率」「会员复购」「二次购买」。一次检索只能覆盖一种说法，多查询能把不同说法都捞一遍。

代价很明确：检索次数翻几倍，延迟上升。所以适合离线预处理或对延迟不敏感的问答，不适合高并发实时接口。

4父子索引：小块检索，大块返回

02 页提过这个思路，这里给出它的完整形态：

层粒度用途
子块（child）100–200 字，按句子切只用来做向量匹配，保证命中精度
父块（parent）800–1500 字，按段落/小节命中后返回给模型，保证上下文完整

实现要点：向量库里存子块向量，同时存一个 parent_id；检索命中子块后，按 parent_id 取回父块，再按父块去重（多个子块可能属于同一父块）。

这个方案的价值在于：它让「检索精度」和「上下文完整性」不再互相牵制，是两个参数各自调到最优，而不是找一个折中值。

5检索中还有一类优化：结构化约束

除了语义，还有很多维度可以用来缩小范围：

  • 时间：只查最近 12 个月，或按时间衰减加权；
  • 来源类型：只查产品文档，不查会议纪要；
  • 权限：按用户所属部门过滤（第 03 页的 ACL）；
  • 文档层级：优先返回「概述」而不是「附录」。

这些条件都应该下推到检索层，而不是取回结果后再筛。否则会出现「取了 20 条，筛完只剩 1 条」的情况。

本页要点

  1. 向量与 BM25 的短板互补，混合检索是工业界的默认配置。
  2. RRF 只用排名不用分数，避免两路分数量纲不一致的问题；两路都在前列的文档会被顶上来。
  3. RAG Fusion 用多查询 + RRF 覆盖不同表述，代价是检索次数成倍增加。
  4. 父子索引把「检索粒度」和「返回粒度」解耦，两个参数各自最优。

9自测

Q1混合检索里为什么不能直接把向量分数和 BM25 分数相加？
这是典型的「不同评分体系不可比」问题。做法要么归一化后再加权（需要调权），要么像 RRF 那样只用排名，绕开量纲。
Q2RRF 中 k=60 的作用是？
k 越大，各名次的得分越接近，融合结果越平滑；k 越小，头部排名的优势越明显。60 是经验默认值，实际可按数据调。
Q3父子索引里，向量库里存的是？
检索要精度，所以用子块向量匹配；返回要上下文，所以回溯父块。只存子块向量能省大量存储，父块原文按 id 取即可。
