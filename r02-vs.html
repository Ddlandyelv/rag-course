微调与 RAG：闭卷考与开卷考

这两个词经常被放在一起比较，但它们根本不是同一层的技术。这一页用一个比喻把边界划清楚：微调改参数，RAG 改输入。

前置：0.1 读完接：0.3 最小闭环 约 14 分钟
这一页在整条链路上的位置
对应环节方案选型 · 对应「RAG vs 微调」
不学卡在哪分不清两者边界，容易做出「用微调更新知识」或「用 RAG 改输出格式」这类错配。
它解决什么给出可执行的判断口诀：缺知识用 RAG，缺格式用微调，都缺就先 RAG。

1一个比喻，先把两者分开

假设你要让一个人通过一场专业考试。有两条路：

路线做法代价对应技术
闭卷考把几千页资料背进脑子，考试时凭记忆作答学费极贵（要反复训练）、改一个字就得重背（重训）、背错了没法查证微调 Fine-tuning
开卷考允许带书进场，考前把书整理好、做一份好用的索引整理书要花功夫（数据工程）、翻书可能翻错页（检索质量）RAG 检索增强生成

这个比喻最精确的地方在于最后一行：开卷考不是变简单了，是把难度从「记忆」转移到了「查资料」。RAG 工程里绝大部分时间，确实花在「怎么把书整理得容易查」上，而不是模型本身。

2关键区别：一个改参数，一个改输入

技术上讲，两者的差别只有一句话：

微调（Fine-tuning）改参数

拿你的数据继续训练模型，改变模型的权重。训练完之后，这些知识「长」在参数里，不占上下文，推理时不额外耗时。

RAG（Retrieval-Augmented Generation）改上下文

模型完全不动。提问时先去外部知识库检索相关片段，把片段和问题一起塞进提示词，让模型「看着资料回答」。

这个区别带来的连锁反应，比想象中大：

维度微调RAG
知识更新重新训练，几小时到几天替换文档，分钟级
成本训练算力 + 标注数据存储 + 检索算力（通常低一到两个数量级）
可溯源做不到天然支持
幻觉可能被抑制，也可能被强化有原文约束，且可要求「没写就说没写」
能力边界能改变「怎么说」——语气、格式、领域表达只能改变「依据什么说」，不会让模型变聪明
失效模式过拟合、灾难性遗忘检索不到、检索错了、检索到但模型没用好

3所以它们不是替代关系

一个常见的误解是「有了 RAG 就不用微调」。实际上两者解决的是不同层面的问题：

  • 微调解决「表达」：让模型学会你的输出格式、行业话术、特定推理流程。比如必须输出固定结构的 JSON、必须按「结论—依据—风险」三段式回答。
  • RAG 解决「依据」：让模型在回答时能看到最新、最准、最私有的资料。

工业界的常见组合是：先用微调让模型学会「怎么答」，再用 RAG 保证「答什么」。反过来的顺序也行，但如果只做 RAG，模型可能拿着一堆正确资料，输出一个格式混乱的答案。

一个判断口诀：缺知识 → RAG；缺格式、缺风格、缺特定推理习惯 → 微调；两者都缺 → 先 RAG 再微调。先 RAG 的理由是它更快见效，能帮你看清问题到底出在「资料」还是「模型」。

4为什么工业界一边倒地先上 RAG

除了成本和时效，还有三个很实际的原因：

  1. 可回滚。检索效果不好，换个分块策略或换个嵌入模型就行；微调训歪了，只能回退版本重来。
  2. 可解释。出问题时能直接看「检索到了什么」，定位是资料问题还是模型问题。微调是个黑箱，效果不好时你只知道「不好」，不知道为什么。
  3. 权限可控。知识库可以按用户做权限过滤——A 部门查不到 B 部门的文档。知识一旦进了参数，就没法按人分权了。

最后一条在 To B 场景里几乎是决定性的。这也是为什么 RAG 最初在企业内部知识问答里爆发，而不是在通用聊天里。

本页要点

  1. 微调 = 闭卷考（背进参数），RAG = 开卷考（现查资料）。
  2. 本质区别：微调改权重，RAG 改上下文。前者慢而深，后者快而浅。
  3. 微调管「怎么答」（格式、风格、话术），RAG 管「依据什么答」。
  4. 工业界先上 RAG 的三个现实理由：可回滚、可解释、可按人做权限过滤。

9自测

Q1如果需求是「让模型严格按公司模板输出采购申请单」，最该做的是？
这是「表达」问题，不是「依据」问题。模板本身很短，放进知识库检索反而多余。正确做法是微调或用结构化输出约束（如 JSON schema、few-shot 示例）。
Q2「RAG 能降低幻觉」的准确机制是？
模型没变，变的是它看到的上下文。有了明确资料，它「编」的空间被压缩；再加一句「未提及请回答不知道」，就多了一道硬约束。但这不等于零幻觉——模型仍可能误读资料或过度概括。
Q3知识库每天更新，为什么 RAG 比微调合适？
知识在外部库里，更新知识 = 更新文件 + 重建索引（通常分钟级）。微调则要重新走一遍训练、评测、上线流程，且训完立刻又开始过时。
